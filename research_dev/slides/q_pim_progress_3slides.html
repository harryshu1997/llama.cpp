Motivation & Novelty
1 / 3
CONVENTIONAL

One GPU, one contended queue

All mixed requests compete for a single GPU. Batching follows only model-local queues; a low-priority burst delays high-priority service.
Q-PIM

Slow-loop residency + fast-loop routing

A slow loop keeps model / operator-island weights resident on phones. A fast loop routes each request to a server or phone island.
Novelty

Mixed-model virtual-queue scheduling across heterogeneous resident operator islands, with SLO-aware batching and fail-closed physical route certificates — one A6000 sustains high-priority BGE while OP15 and OP12 independently process low-priority Gemma prefixes.

Phones are PIM-style active far memory that computes on resident weights — not coherent server memory.
